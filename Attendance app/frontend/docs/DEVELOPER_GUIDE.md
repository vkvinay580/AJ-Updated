## Firebase Cloud Messaging

Firebase project `aryan-80155` contains a dedicated Android app for package `aryan.attendance`. Gradle applies `com.google.gms.google-services` whenever `android/app/google-services.json` is present. `PushMessagingService` initializes Firebase, requests Android notification permission, registers and refreshes the FCM token through the authenticated `/api/notifications/device-token` endpoint, removes the current token on logout, and handles foreground, opened-app, and background messages. Notification payloads are rendered by Android in the background; the Dart background handler renders only data-only messages so one FCM delivery cannot create duplicate alerts. The existing authenticated notification polling remains a delivery fallback.

Laravel sends FCM HTTP v1 messages through `FirebaseCloudMessagingService`. Set `FIREBASE_PROJECT_ID=aryan-80155` and `FIREBASE_SERVICE_ACCOUNT` to an absolute path containing the private service-account JSON. Store that JSON outside Git, restrict it to the deployment account, and never place its private key in an environment example, APK, log, or documentation. The default deployment path is `storage/app/firebase/service-account.json`; create its parent directory privately, clear Laravel's configuration cache after changing `.env`, and verify that the Firebase Cloud Messaging API is enabled for the project. Invalid or unregistered device tokens are removed after Firebase rejects them.

The direct Attendance APK linked from AJ's `/login` page is built with `flutter build apk --release --no-pub` (or the equivalent explicit production `API_BASE_URL`) and copied from `build/app/outputs/flutter-apk/app-release.apk` to AJ's `public/downloads/aryan-attendance.apk`. The current local build has no release keystore and uses debug signing; replace it with the properly release-signed APK before distributing updates to devices with the Play Store signed version installed.

Production Laravel settings are documented in `../../Backend/.env.production.example`. Deploy the backend and database before publishing the APK, create DNS and TLS for `attendance.aryangold.in`, run all Laravel migrations, and verify `GET /api/app/update`. The current AJ integration reads Attendance through `/api/business/*`; legacy outbound employee sync stays disabled unless `ARYANGOLD_EMPLOYEE_SYNC_URL` is deliberately configured.

Laravel serves Flutter web files with an explicit extension-to-MIME-type map. This keeps the web build usable on cPanel PHP installations where the optional `fileinfo` extension is unavailable; adding a new generated asset type requires adding its safe MIME type to `FrontendWebController::contentTypeFor()`. Production verification must check the HTML shell plus `flutter_bootstrap.js`, `main.dart.js`, `AssetManifest.bin`, and a CanvasKit `.wasm` response.

Attendance check-in, check-out, and fraud-proof selfie validation also supports cPanel installations without `fileinfo`. These uploads use Laravel's required/file/5 MB checks plus `DecodableImage`, which verifies the actual image dimensions and format with `getimagesize`. Stored attendance filenames use the detected JPG, PNG, GIF, BMP, or WebP format rather than the client-supplied extension. Keep this content-based rule on attendance photo endpoints; Laravel's built-in `image` rule calls Symfony MIME guessing and throws a server error when no MIME guesser is installed.

All employee API image uploads use that same `DecodableImage` path: attendance and fraud photos, profile photos, ID-card photos, site-visit photos, TE-tracker photos, and optional passbook images. File naming and ID-card storage derive extensions from decoded image content rather than client filenames. Do not reintroduce Laravel's built-in `image` or `mimes` rules on these endpoints while production PHP lacks `fileinfo`.

Employee passbook uploads use the same `DecodableImage` rule and detected safe extension, so bank-detail submission also works without `fileinfo`. The encrypted account-number, IFSC, UAN, Aadhaar, and PAN columns use `TEXT`: Laravel ciphertext is longer than the validated plaintext and must not be stored in the legacy 20-50 character columns. Migration `2026_10_15_000002_widen_encrypted_bank_detail_columns` updates both pending bank-detail requests and the verified `employeedetails` destination.

Encrypted fields in `employeedetails` are required by the legacy schema and use `EncryptedStringOrEmpty`: populated values remain encrypted, while missing optional UAN, Aadhaar, or PAN values persist as empty strings instead of being converted to SQL `NULL`. Pending bank-detail request fields remain nullable and continue using `EncryptedString`. This distinction prevents individual and bulk verification from failing while creating an employee-details row.

## Employee documents

The `employee_documents` table stores manually uploaded employee files: employee ID, document type, optional display title, optional payslip period, original filename, MIME type, size, uploader, and a private storage path. Files use the Laravel local disk under `storage/app/private/employee-documents/{employee_id}`; they are not served from `public/storage`.

HR Admin users manage manual documents from the employee edit page. Accounts users use the **Employee Documents** sidebar page to search for an employee and manage their files. Uploads are limited to PDF, DOC, and DOCX files up to 20 MB; manual payslips require a `YYYY-MM` period.

`GeneratedEmployeeDocumentService` adds eligible system documents to `GET /api/employee/documents` without creating database rows or storing redundant PDFs. It requires positive salary for the offer letter, valid DOJ for the experience letter, positive salary plus attendance/regularization activity in a completed month for each payslip, and valid last-working date for the relieving letter. Payslip months are bounded by DOJ and last-working date. `EmployeeSalarySummaryService` mirrors the employee salary endpoint's attendance classification, Sunday/night-shift handling, salary proration, advance window, PF and security-deposit calculations. `EmployeeDocumentPdfFactory` renders all four documents through `ProfessionalPdf` using built-in PDF primitives, avoiding new cPanel extensions or Composer PDF dependencies.

The authenticated index returns both generated and uploaded files with relative signed download URLs that expire after 15 minutes. `GET /api/employee/generated-documents/{employee}/{type}/download` rechecks current eligibility before rendering a PDF; payslip links carry a signed `period=YYYY-MM` query. `GET /api/employee/documents/{employee}/{document}/download` retains ownership checks for private uploaded attachments. Keep signed routes private to API-generated URLs and include `storage/app/private/employee-documents` in local and production backups.

## AJ business integration

The Laravel API is the source of truth for business-portal employees, active branches, `employee.assigned_branch_id`, and `employee_app_credentials`. AJ calls `GET /api/business/directory`, `POST /api/business/assign`, and `POST /api/business/login` from its server only. Every request must carry `X-Aryan-Integration-Key`, matched in constant time against `ARYANGOLD_BUSINESS_INTEGRATION_KEY`. Never expose this key to browser code. Production AJ and Attendance must use the same independently generated secret; local development uses the ignored environment files. Set the same 32-byte (64-character hexadecimal) value as `ATTENDANCE_INTEGRATION_KEY` in AJ's `.env.local` and `ARYANGOLD_BUSINESS_INTEGRATION_KEY` in the Attendance backend's `.env`. After rotating it, restart AJ and clear Laravel's configuration cache before testing the integration.

The assignment endpoint updates `assigned_branch_id` and optionally creates or replaces the branch-specific password hash. The login endpoint requires an active employee, active branch, matching current assignment, matching branch credential, and valid password. The directory response intentionally omits password hashes and other personal data.

`POST /api/business/login` validates those conditions in a defined order and returns Laravel JSON validation errors suitable for direct display by AJ: unknown employee or bad password, inactive employee, missing assignment, invalid/inactive branch, assignment mismatch, or missing branch credential. AJ sends `Accept: application/json`, extracts the first field validation message, and validates successful response shape before creating a branch session so an incomplete upstream payload cannot cause a `branchId` runtime error.

The recovered `Backend/build/web/main.dart.js` API defaults were changed from the production hosts to `http://127.0.0.1:8000/api`. This adjustment belongs only to this local compiled build and must be repeated if it is restored from the archive. Pending Laravel migrations are applied only to the local database.

MariaDB required a supporting `employee_id` index on `id_card_submissions` before the soft-delete migration could drop its unique index. The supporting index was added to the local database, then all pending migrations completed. Frontend HTML, its bootstrap script, its compiled JavaScript, and the administrator login returned HTTP 200. Authenticated workflows require account credentials and were not exercised.

`Backend/public/index.php` delegates to the backup's cPanel entry point. Start the web server from `Backend` with:

```powershell
& E:/xampp/php/php.exe artisan serve --host=127.0.0.1 --port=8000
```

MariaDB must be running before using database-backed pages. Existing databases were left intact. No queue worker or scheduler is started for this local preview.
